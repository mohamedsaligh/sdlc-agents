01

The idea in one glance

The problem

  • 20+event-driven Java services; one payment crosses 10 to 15 of them before it settles.
  • 0services named in a Jira. Every change starts by copying a baseline market and hoping the technical layer still fits.
  • 2,000engineers across regions, markets and products. Pasting the whole platform into context does not scale and does not repeat.

The answer

Shape in the map, data live·Thin agents, thick map·Evidence gates·Everything is a file

  • Map records what each service touches, never the rows. Rows are fetched live per market.
  • Agents route, load, reason and write. None of them reads the whole platform.
  • Gates are scores backed by evidence. Below the line, the agent asks instead of planning. Humans approve.
  • Files hold every step of every run, so any result can be replayed, audited and distributed.
02

High-level design

Solution agentSix small steps, each reading named files and writing named files. Output is a plan or a list of questions, never a guess.
Builder agentDeliberately boring. Approved plan in, pull request out, with coverage and traceability attached. A failed build stops the run.
Maintenance agentCompares design docs, manifests, code and real traces. Proposes manifest diffs; humans merge them.

Change buckets · assigned by the agent, corrected by people

ONBOARDINGNew market or new market × clearing × product combination, often 100+ epics. One base pass picks the baseline, lists the full scaffolding and writes a shared onboarding-context; engineers then take work-package slices that read it instead of rediscovering it.
MINOR_INITIATIVEA new service or new feature added to an existing flow. Single pass, radius usually 2 to 5 services.
ENHANCEMENTBehaviour change on a live product. Single pass, radius 1 to 3 services.
BUG_FIXDefect on a live product with expected behaviour already defined. Smallest radius, strictest diff.
04

Rollout

PHASE 1

Map

Manifests for every service, __DEVCTL__ contracts, vocabulary, triangulation of design docs against code and one traced payment.

EXITEvery hop of a real payment appears in the manifests; validator and drift check pass.
PHASE 2

Solution agent

Run end to end on one real Jira, by hand, step by step, until the plan is something a junior could implement correctly.

EXITOne Jira in, three documents out, every score with evidence. This is the demo.
PHASE 3

Builder agent

Approved plan to pull request, with coverage delta and traceability matrix, stopping on any failure.

EXITPR merged by humans with zero files outside the plan and zero unmapped changes.
PHASE 4

Distribution

Map and agents published as a versioned bundle on __AI_PLATFORM__; local CLI exposes them over MCP to Copilot and Claude Code.

EXITTwo engineers in two regions get the same radius for the same Jira at the same map version.
